# TODO: Home Assist — управление устройствами Xiaomi

Кроссплатформенное приложение (Windows, macOS, Linux, Android, iOS) для управления
устройствами экосистемы Xiaomi / Mijia вместо официального Mi Home. Главное отличие
от Mi Home — **все регионы серверов и все аккаунты в одном списке устройств**:
например, из России управлять одновременно устройствами, привязанными к региону
«Россия», и устройствами, привязанными к региону «Китай».

---

## 0. Ключевые факты, на которых строится архитектура

- [ ] Проверить на практике и зафиксировать в `docs/regions.md`:
  - Аккаунт Xiaomi **глобальный**, а устройство привязано к **серверу региона**
    (`cn`, `ru`, `de`, `us`, `sg`, `i2` (Индия), `tw`). Один и тот же аккаунт после
    входа может запрашивать список устройств у любого региона.
    → Вероятно, отдельный аккаунт для Китая не нужен, но поддержку нескольких
    аккаунтов делаем в любом случае.
  - Облачный API: `https://api.io.mi.com/app` для `cn` и
    `https://{region}.api.io.mi.com/app` для остальных.
  - Локальное управление (miIO по UDP 54321) **не зависит от региона** вообще —
    нужны только IP и токен устройства в той же сети.
  - Часть китайских устройств отказывается работать с не-китайским регионом
    в Mi Home — это ограничение прошивки/привязки, а не нашего приложения. Такие
    устройства оставляем в регионе `cn` и просто читаем их оттуда.
- [ ] Выяснить `model` вентилятора ZFSLFS01DM (вид `dmaker.fan.xxx`) и сохранить
      его спецификацию MIoT как первое эталонное устройство для тестов.

## 1. Решения по архитектуре (зафиксировать до начала кода)

- [x] **Стек UI:** Flutter — одна кодовая база под 5 платформ.
      Альтернатива для сравнения: Tauri 2 (Rust + веб-UI), мобильная поддержка у него моложе.
- [x] **Ядро протоколов:** сначала на Dart внутри Flutter-проекта.
      Выносить в Rust (`flutter_rust_bridge`) только если упрёмся в производительность
      или понадобится CLI/сервер без UI.
- [ ] **Принципы кода** (записать в `CONTRIBUTING.md`):
  - минимальная когнитивная сложность: короткие функции, ранний выход вместо
    вложенных `if`, никаких «умных» абстракций без второго реального применения;
  - слои не знают друг о друге лишнего: `transport` → `protocol` → `device model` → `UI`;
  - каждый транспорт (облако / локально) реализует один общий интерфейс
    `DeviceTransport` с методами `getProperties`, `setProperty`, `callAction`.
- [ ] Структура репозитория:
  ```
  lib/
    core/
      accounts/      # аккаунты, сессии, хранение секретов
      cloud/         # MiCloud: вход, подпись запросов, регионы
      local/         # miIO/MIoT по UDP: рукопожатие, шифрование
      spec/          # загрузка и кэш MIoT-Spec-V2
      devices/       # единая модель устройства и выбор транспорта
    ui/
  test/
  docs/
  ```

- [ ] (код написан, на реальном аккаунте не проверен) Обработка капчи (показать картинку пользователю, отправить ответ).

- [ ] Обновление сессии при истечении `serviceToken` без повторного ввода пароля,

      `client_id`; чужой `client_id` в релиз не выпускать.

### 2.2 Подпись и шифрование облачных запросов
- [x] Реализовать `signed_nonce` и шифрование RC4 (актуальный режим API).
- [ ] Реализовать старый режим подписи HMAC-SHA256 как запасной.
- [x] Модульные тесты на эталонных векторах (взять из открытых реализаций,
      например Xiaomi Cloud Tokens Extractor / `micloud`).

### 2.3 Список устройств по всем регионам
- [x] Параллельный запрос `/home/device_list` ко всем регионам.
- [x] Ошибка или тайм-аут одного региона не ломает остальные — показываем
      частичный результат и отметку «регион недоступен».
- [x] Для каждого устройства хранить: `did`, `model`, `name`, `region`, `accountId`,
      `localip`, `token`, `isOnline`, `parent_id` (для устройств за шлюзом).
- [ ] Кэшировать список локально, чтобы приложение открывалось без сети.
- [x] Настройка «какие регионы опрашивать» (по умолчанию: все).

### 2.4 Управление через облако (MIoT)
- [x] `/miotspec/prop/get`, `/miotspec/prop/set`, `/miotspec/action`.
- [ ] Для старых устройств без MIoT — `/home/rpc/{did}` (miIO-команды).
- [x] Каждый запрос уходит на сервер **региона устройства**, а не текущего региона
      приложения.

### 2.5 Спецификации MIoT-Spec-V2
- [x] Загрузка `https://miot-spec.org/miot-spec-v2/instances?status=released`
      (соответствие `model` → `type`) и `.../instance?type=<urn>`.
- [x] Кэш спецификаций на диске с датой обновления.
- [x] Разбор: сервисы (`siid`), свойства (`piid`, формат, диапазон, список значений),
      действия (`aiid`).

### 2.6 Универсальный UI устройства
- [x] Экран устройства строится **из спецификации**, а не вручную:
      `bool` → переключатель, диапазон → слайдер, список значений → выбор,
      действие → кнопка, только чтение → строка значения.
- [ ] Первым полируем вентилятор ZFSLFS01DM: питание, скорость, режим,
      поворот, охлаждение/увлажнение, уровень воды, таймер, блокировка кнопок.
- [x] Периодический опрос состояния открытого устройства (например, раз в 5–10 с).

## 4. Локальное управление (без облака)

- [ ] Протокол miIO: рукопожатие (hello-пакет), получение `device id` и штампа
      времени, шифрование AES-128-CBC (ключ = MD5(token), IV = MD5(ключ + token)),
      контрольная сумма MD5.
- [ ] Команды MIoT по локальному каналу: `get_properties`, `set_properties`, `action`.
- [ ] Поиск устройств в сети: широковещательный hello на `255.255.255.255:54321`,
      дополнительно mDNS (`_miio._udp`).
- [ ] Сопоставление найденных IP с устройствами из облака по `did`.
- [ ] Выбор транспорта: **сначала локально, при неудаче — облако**; ручное
      переключение в настройках устройства.
- [ ] Режим «только локально»: ввод IP и токена вручную, без аккаунта Xiaomi.
- [ ] Предупреждение: после сброса или повторной привязки устройства токен меняется.

## 5. Платформы

### Общее
- [ ] Хранение секретов (пароли не храним вообще; токены сессий и устройств —
      в системном хранилище): `flutter_secure_storage`
      (Windows Credential Manager, macOS/iOS Keychain, Linux libsecret, Android Keystore).
- [ ] Локализация: русский (основной), английский.
- [x] Тёмная и светлая темы.

### Windows / macOS / Linux
- [ ] Иконка в системном трее и быстрые действия (вкл/выкл избранных устройств).
- [ ] Запрос разрешения брандмауэра Windows для UDP.
- [ ] Сборки: MSIX или установщик для Windows, `.dmg` для macOS
      (подпись и нотаризация), AppImage или Flatpak для Linux.

### Android / iOS
- [ ] iOS: разрешение «Локальная сеть» (`NSLocalNetworkUsageDescription`,
      `NSBonjourServices`), иначе локальный UDP не заработает.
- [ ] Android: проверить широковещательный UDP в Wi‑Fi, при необходимости `MulticastLock`.
- [ ] Виджеты на главном экране для избранных устройств (второй этап).

# Repository Guidelines

## Структура проекта

Home Assist — приложение Flutter для устройств Xiaomi/Mijia на Windows, macOS, Linux, Android и iOS. Точка входа — `lib/main.dart`. В `lib/core/` находятся аккаунты (`accounts/`), облачный API (`cloud/`), спецификации MIoT (`spec/`) и управление устройствами (`devices/`). Экраны, тема и виджеты размещены в `lib/ui/`, демонстрационные данные — в `lib/demo/`. Сохраняйте разделение интерфейса и сетевой логики.

Тесты находятся в `test/core/` и `test/ui/`; образцы спецификаций — в `test/fixtures/spec/`, подмены облака — в `test/support/`. Шрифты и иконки лежат в `assets/`, снимки экранов — в `docs/screenshots/`, HTML-прототип — в `design/`, сценарии установщиков — в `packaging/`.

## Команды разработки

Используйте Flutter, совместимый с Dart `^3.13.4`; в CI закреплён Flutter `3.47.5`. Выполняйте команды из корня репозитория:

- `flutter pub get` — загрузить зависимости.
- `flutter run` — запустить приложение; `flutter run --dart-define=DEMO=true` — открыть демо.
- `dart format lib test` — отформатировать исходники и тесты.
- `flutter analyze` — проверить код с правилами `flutter_lints`.
- `flutter test` — выполнить обычные тесты.
- `flutter build windows --release` — собрать Windows; для других платформ используйте `linux`, `macos`, `apk` или `ios` на подходящей системе.

CI проверяет формат командой `dart format --output=none --set-exit-if-changed lib test`, анализ и тесты.

## Стиль и именование

Используйте отступы в два пробела и форматирование `dart format`. Файлы называйте `lower_snake_case.dart`, классы — `UpperCamelCase`, методы и переменные — `lowerCamelCase`. Снижайте когнитивную сложность: небольшие функции, ранние возвраты, минимум вложенности. Пояснения и комментарии пишите по-русски; идентификаторы сохраняйте в принятом стиле Dart.

## Тестирование

Используйте `flutter_test`, `fake_async` и подменённые сетевые клиенты. Имена файлов заканчивайте на `_test.dart`, повторяя структуру модулей. Исправления ошибок сопровождайте проверкой воспроизводимого сценария. Числовой порог покрытия не задан. Отдельный тест запускайте, например, через `flutter test test/core/devices/device_repository_test.dart`.

Для обновления снимков в PowerShell выполните `$env:SCREENSHOTS='1'`, затем `flutter test test/screenshots`; после завершения удалите переменную через `Remove-Item Env:SCREENSHOTS`.

## Коммиты и запросы на слияние

Следуйте истории: короткий русский заголовок с действием, например «Обновить README: вход по QR-коду». Объединяйте изменения одной задачи. В описании запроса укажите причину, результат и выполненные проверки; приложите связанную задачу, если она есть, и снимки при изменении интерфейса.

## Секреты и инструкции агентам

Не добавляйте реальные пароли, сессии и токены в код, журналы или тестовые данные. Сессии храните через системное защищённое хранилище. Общайтесь и документируйте изменения по-русски; английский используйте для кода и технических терминов.
